GV 2026 Letters Processing System

How a trainee team turned a month-long manual mail-merge job into an overnight, automated server process.

The problem

As trainees in the IMU Applications and Projects team, we were asked to help the Real Estate Revenue department process about four hundred thousand (400,000) GV 2026 notice letters, fast. Customers and businesses that own property had to receive them by email in time to review them and raise enquiries.

The manual process had three steps for every batch:

  1. Mail merge a spreadsheet into Microsoft Word.
  2. Cut the merged document into single letters with a third-party app.
  3. Rename each PDF uniquely for its customer before emailing it.

Each of us could only get through about 5,000 letters a day, and that took the whole working day. Our laptops crashed when we pushed bigger batches, the third-party tool sometimes corrupted letters, and every batch had to be sample-checked by hand. We were never going to make the deadline.

What I built

I built a server desktop application, out of pure necessity, that runs the whole pipeline on its own: spreadsheet in, cleanly named individual PDFs out. It uses multi-threading to process letters at the same time and estimates how long each run will take.

I worked with a senior Applications Engineer to get Virtual Machine access on an available server, set the application up there and ran it at full scale. Instead of our 5,000-letter limit, it processed batches of up to 100,000 letters overnight while we were sleeping. We came back the next day to accurate letters, ready to send to the email server.

Then I kept improving it:

  • A GUI built with Tkinter, so anyone on the team can run it.
  • Grouping the output letters into folders.
  • Robust error handling so each batch is processed cleanly.
  • A log of every run written to a temporary text file in the Windows temp folder.
  • Graceful handling of duplicates and unexpected data.
  • A User Manual for the team.

The result

A job that could have run more than a month past the deadline was finished in a matter of days. I am truly proud of it, and I learned a lot about what goes into an internal application, from the server setup to writing the user manual.
